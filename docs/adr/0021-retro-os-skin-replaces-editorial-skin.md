# 0021 — Retro-OS Skin Replaces the Editorial Skin

## Status

Accepted — 2026-11-01. Confirms and extends [0001 — Vanilla static, no build step](0001-vanilla-static-no-build.md) (the zero-dependency constraint is load-bearing and survives the redesign untouched); supplements [0005 — Risk Radar as shareable hero](0005-risk-radar-shareable-hero.md) (the radar keeps its label and score-band contract; only its rendering goes period) and [0018 — First-visit language routing](0018-first-visit-language-routing.md) (its routing semantics are unchanged; the language affordance it paired them with became a system dialog, then the taskbar Language Toggle that swaps the page in place — see [0019](0019-in-page-locale-switching.md)). Records the owner-approved design of spec issue #36; implements the navigation model already decided in [0020](0020-wizard-navigation-with-explicit-commit.md). Supersedes the editorial skin ("Surya") as the site's presentation layer; the editorial-skin note in `docs/architecture.md` and its design-DNA artifact describe the retired state. *(Amended by tickets #59–#68, recorded by #69: the single-window reading of this decision is amended — the results stage became a **three-program desktop** with a window manager, its own persistence record and two reversals. The rejection of that manager in "Alternatives considered" below was written for this decision's original scope; it is kept visible as history and reopened where the reasoning no longer holds.)*

## Context

The assessment shipped wearing an editorial portfolio skin — serif display type, a soft-shadowed card system, one orange accent, and a generic fade between views. It read as a template, not a product: the quiz was forgettable, the results screen shared nothing with the landing, and the only "identity" was borrowed. The owner decided to recreate the experience of running the assessment as a native program on a Windows 95/98 machine — boot, window, taskbar, radio buttons, wizard navigation, system sounds — as the site's permanent visual language.

The architecture made this a styling problem, not a rewrite: the site already layered a single override skin on top of structural stylesheets (`docs/architecture.md`), so the presentation could be swapped wholesale while the content pipeline — Question Banks, scoring, validation, the Proxy Worker — stayed byte-identical. ADR 0001's no-build rule and the static deploy narrow how far the illusion can be built: no animation libraries, no framework components, no generated assets. *(#51 kept that rule intact: the Chinese pixel face ships as an offline, repo-side subset committed with its license — a checked-in artifact, not a page build; see `fonts/PROVENANCE.md` and ADR 0001's amendment.)*

## Decision

**Clean cutover, same seam.** One new override skin replaces the editorial one, linked last exactly as its predecessor was. The editorial skin file and its design-DNA artifact are deleted; a new design-DNA artifact documents the new system. The base stylesheets keep their semantic token aliases — the skin only re-points values — so no structural file ever learns the palette.

**Stock Windows 95 values, retro-inspired fidelity.** Silver `#C0C0C0` chrome with white/gray/dark-shadow bevels, navy `#000080` title bars and selection, teal `#008080` desktop, black-on-white fields; the classic 16-color system set supplies status colors — dark variants wherever a status color is text, bright tints for graphic fills only, keeping the contrast rationale the retired skin had documented. Surfaces are solid high-color; 1px dither appears only on disabled/pressed-in chrome. The editor's orange is gone. Fidelity bends to legibility: UI chrome is period, but Scenario and Feedback prose stays modern readable type at comfortable sizes with 44px touch targets.

**Self-hosted type, never fetched.** The chrome face is a metric-compatible MS Sans Serif clone (W95FA) under SIL OFL 1.1, verified for commercial web embedding, committed with its license text and provenance, pinned to a Latin `unicode-range`; body type is a readable system sans. The Chinese Bank Variant page leads with the era-accurate SimSun/宋体 stack via the existing token-swap mechanism — its chrome reads period, its prose reads clean. Zero third-party font requests at runtime. *(Amended by #51, recorded by #57: two faces joined the set — **Silkscreen** for the Welcome Splash's display catchphrase and a **Fusion Pixel 12 SC subset** carrying the Han half of `--font-heading` on the Chinese page, both OFL 1.1, both self-hosted with license text and provenance in `fonts/`, each pinned by `unicode-range` so Han runs and Latin runs never land on the other's face. The Chinese typography rules that once lived in their own stylesheet now sit inside the skin, gated on `html[lang^="zh"]`, so a page that swaps language at runtime restyles correctly. See `fonts/PROVENANCE.md` for the licenses, the `unicode-range` reasoning, and the offline subset regeneration.)*

**A thin OS shell around the old view pipeline.** New modules on the established `App.*` seam: a boot splash (once per tab via a `sessionStorage` flag, reduced-motion bypass), a window frame with live title-bar controls and a taskbar (Start menu, program button, per-minute clock, language tray chip), a window-manager state machine, a reusable system-dialog primitive (End Program confirmation, language offer), a WebAudio synth sound layer (no audio files) gated to desktop widths and armed on the first user gesture, and the wizard decision core of ADR 0020. The views themselves — landing, quiz, results, Review — are what they always were inside this shell. *(Amended by #49–#53, recorded by #57: the title-bar controls draw real glyphs rather than typed characters (#49); the taskbar's per-minute clock became the two-segment EN/中文 **Language Toggle** (#50), which since #55–#56 swaps the page in place ([0019](0019-in-page-locale-switching.md)); the dialog primitive's language offer is retired (#54) so it serves End Program, the About window and the 404 idiom; the window keeps a fixed height with the **Quiz Chrome** status bar pinned inside it and only the client area scrolling (#52); and the landing was rebuilt as the compact **Welcome Splash** box (#53).)*

**The results stage became a three-program desktop.** *(Shipped by tickets #59–#68, recorded by #69; this amends the thin-shell paragraph above and reopens the rejected Alternative below.)* What changed is not taste but scope: the results stage carries several multi-part artifacts that belong to **different moments** — the Progression Title, Risk Radar and Blind-Spot Bars are the score report, settled at the click; the Action Plan arrives seconds or many seconds later over the Provider; the Deep-Dive Prompt is the artifact the Participant copies out and takes to their Agent. Presented as one scrolling column they arrived as one lump, and the late-arriving plan landed on top of the numbers that explain it: the scroll conflated the report, the recommendation and the takeaway. A three-program desktop gives each its own surface, and each surface keeps the arrangement the Participant put it in.

The shipped shape, as the modules record it:

- **Three programs on one Window Record map.** `js/desktop-core.js` is the DOM-free state model — one Record per program Id (`quiz`, `action-plan`, `deep-dive`) carrying Mode, Geometry, Last Geometry, Last Mode and stacking order `z`, plus the transitions and the mode-derived consequences (visible, taskbar membership, focus eligibility) that `js/windows.js` renders instead of copying. Only the Quiz window exists from boot; the other two are born by **Arrival** — the Action Plan when its content settles, the Deep-Dive Prompt minimized at the Finish Commit. An absent Record is not a mode: an unarrived program is painted nowhere and listed nowhere.
- **Stacking with raise-on-interaction.** Any pointer interaction inside a frame raises it and makes it active; `js/desktop-core.js` `raise` is the only writer of `z`, and arrival never raises, never focuses and never scrolls — a newcomer that must not cover the window being read (the Action Plan) is inserted **below** the active window.
- **Designed defaults plus a 24 px cascade.** Each program has a designed default Geometry; a window born while another is focused takes that window's origin plus a 24 px down-right **Cascade**. Drag and corner-grip resize write Geometry through the core under the controller's clamp (minimum size, title bar never under the taskbar, walls crossed and returned inside one gesture); writes are refused while maximized and on the mobile layout.
- **Desktop shortcuts, and the two taskbar rules.** A fixed top-left column of three era icons — one per program, always present whether or not the program runs, launched by double-click or Enter/Space through the controller's one `launchProgram` gesture (Arrive an unarrived program, restore a put-away or minimized one at its Last Mode and Last Geometry, otherwise Raise the running window; never a second window). On the desktop layout the taskbar lists **EXACTLY the running windows** in the stable program order — a hidden window has no button, the Quiz included, and its shortcut is the way back. At ≤768px there is no shortcut column and no geometry: the layout is single-program, one frame fills the screen above the slim taskbar, the chrome reduces to [×], and the taskbar's **three program switches are permanent** — the only route between programs, one pressed entry per screen.
- **Put Away, not close.** There is no `closed` mode and no way to delete a program: [×] on the desktop and on the mobile desktop stage is the core's `hide` — the window leaves the screen, its Record, Report and arrangement survive, and the desktop hands over to the window under it. Minimize traces the window down to a taskbar entry it still restores; only `resetPrograms()` destroys Records, and only the destructive paths run it. Flow stages (landing, quiz) have no desktop and still answer [×] with the End Program question.
- **The inert keyboard floor.** Only the focused window answers the keyboard: `paintFrame` puts `inert` on every region of a background frame except its two pointer handles, so Tab never lands in a window the Participant is not working in while a press on an inert control retargets to the live root and raises it. Frames are labelled groups, **never `aria-modal`**; there is **no Alt+Tab interception** and no focus trap — the desktop stays one Tab order. Escape's window tier puts the focused window away and hands focus back to the taskbar entry or the shortcut the Participant came through; above it sit the system dialog, About and the Start menu.
- **A per-tab desktop Record, written only at the Finish Commit.** `js/desktop-store.js` keeps `quiz-desktop` in **sessionStorage** — never inside `quiz-session`, never in localStorage — holding the structural bank hash, the answers, the language, every Window Record and the active program. `js/quiz.js` writes it exactly once, inside the hand-off beat after the desktop comes into being; it is never written on load and never for an uncommitted Session. `js/main.js` asks `restore(bank)` before first paint: the Records go back through `loadSnapshot` (all-or-nothing), the report is **recomputed** through `App.Scoring` under the page's Bank Variant, and the results view renders directly with no `quiz_completed`; `js/boot.js` suppresses the boot splash and takes the landing out of the first paint while a Record is pending. Stale hash, incomplete answers, malformed or unparsable payloads and unavailable storage all discard quietly.
- **The Action Plan cache rides in that Record.** One settled `{narrative, actions}` payload **per report per language**: `captureAtCommit` starts the map empty, `savePlan` merges a late resolution under the language that issued the request (never into a Record a Retake or Quit has cleared, never for a superseded Completion), and a restore brackets its single render with `beginPlanRestore`/`finishPlanRestore` so a cached language re-renders with no request at all and a miss queues exactly one.

**Two reversals, recorded explicitly.** *(#66.)* First: **Quit now clears the Session.** This ADR's original Consequences promised that "the window never truly closes (End Program returns to the landing and the Session survives)" — that survives only for the non-destructive gestures. The window [×] still never touches persistence, and End Program's No/Escape still changes nothing, but the Start-menu **Quit** and the menu-bar **Retake** are the run-enders: both answer a confirmation and both run the one destructive tail, `App.Windows.endRun()`, which clears the Session, clears the per-tab desktop Record whole (cached plans included), shows the landing page, then tears the desktop down through `resetPrograms()` — Records destroyed, not hidden — so a reload restores nothing. Second: the **desktop Record is separate from the Session**, and it is what preserves the explicit-commit contract of [0020](0020-wizard-navigation-with-explicit-commit.md). ADR 0017's localStorage Session keeps its pick-by-pick writes and its language-invariant, structurally-hashed record; the desktop's own state lives apart, per tab, and is committed once — at the Finish Commit, never before. Nothing about the Session's shape changed, and no desktop state ever rides on an uncommitted run.

**One known discrepancy with ADR 0017, kept on purpose.** ADR 0017's Consequences state that "returning with a complete Session shows the results". That sentence describes the boot path as it was before #63 and is no longer what the shipped code does: a **complete but uncommitted** Session — every Question holding an Option, the [Finish] click never made — resumes on the **last Question with [Finish] live**, and the Participant commits it. `js/quiz.js` never treats a fully-answered record as Completion any more, because ADR 0020 made Completion a decision rather than a side effect, and the desktop Record's restore is a different door: it only opens for a run whose commit happened. Showing results from the Session alone would silently complete an assessment the Participant never finished, fire the analytics contract at the wrong moment and start the Action Plan request for a run that owes one. So the boot path **must never be "fixed"** into automatic Completion; the uncommitted-complete case is the designed behaviour, asserted by `tests/js/test-quiz.js`, and ADR 0017's sentence is read as superseded on that point.

**Era-mechanical motion only.** Views open with a wireframe border trace (`steps()` timing, ~200ms), cards swap with a client-area wipe, Progress Fill and Blind-Spot Bars fill as discrete segments. Every trace, wipe, and width transition is disabled under `prefers-reduced-motion` — including the two the retired skin had left ungated. No motion library is permitted; motion is CSS or nothing.

**Contracts that did not move.** Scoring, the Session record itself (`quiz-session`, ADR 0017 — its key, its structural hash, its language invariance and its pick-by-pick writes), the five-event analytics contract, the radar's AST-ID + percentage labels and score-band encoding (ADR 0005), the Action Plan's LLM Path / Deterministic Fallback duality (ADRs 0007–0010), Chrome Strings with missing-id hard failure (ADR 0015), and first-visit routing behavior (ADR 0018) are unchanged. New interface copy entered the base dictionaries in both languages; new storage keys are a per-tab boot flag (sessionStorage) and the sound preference (localStorage, a preference like Language Preference, never version-stamped). *(Amended by #63–#66, recorded by #69: the Session's shape still did not move — what changed is who may clear it, per the reversals above, and `quiz-desktop` joined the storage list as the per-tab desktop Record.)*

## Consequences

- The site has one identity, end to end, including the 404 page and the regenerated Open Graph share card — and it is verifiable: the presentation-layer section of `docs/architecture.md` and `design-dna-retro-os.json` describe the shipped system.
- Adding a language stays a bank + dictionary + page affair (ADR 0015's cost model survives; since #51 the language's typography is a gated rule set in the shared skin, not a sheet only that page links); adding a component means bevel classes from the skin and strings from both dictionaries — the seam discipline continues.
- Two small, deliberate lies to the machine exist by design: the app never actually boots (the splash masks load, it does not gate it), and a window never truly closes (its [×] puts it away; End Program returns to the landing and the Session survives). Both are documented in their modules. *(Amended by #59–#68, recorded by #69: the second lie narrowed rather than vanished. A window's [×] still never destroys anything and End Program still leaves the Session untouched — that promise is now load-bearing, because the put-away gesture is how every one of the three programs leaves the desktop. What was reversed is who may end a run: only the confirmed **Quit** and **Retake** destroy state, and they destroy the Session, the per-tab desktop Record and the desktop's program Records together through `App.Windows.endRun()`. The splash lie stands, and on a restore the splash is suppressed outright.)*
- The headline font cannot render CJK or color emoji; the `unicode-range` pin and the system stack make that a non-issue for text, and the headless-emoji nit is an environment artifact, not a product one. *(Amended by #51: Chinese chrome/headings now render on a self-hosted Fusion Pixel 12 SC subset pinned to CJK ranges; prose and non-Chinese pages keep the system stacks.)*
- Test surface grew where behavior lives: boot gating, wizard decisions, window state, sound gating, and shell cadence all test headless through the one existing seam; pixel-level fidelity remains browser-verified, as it always was.

## Alternatives considered

- **Keep both skins with a theme switcher.** Rejected: two design languages halve the QA surface each can trust, and the editorial skin's rounded, soft-shadowed grammar actively contradicts beveled chrome at the component level — the switcher would be a permanent reconciliation tax for nostalgia with no participant benefit.
- **Modernized "retro-flavored" palette (softer grays, brighter navy).** Rejected: the exact stock values are the identity; a tasteful approximation reads as generic dark-mode-ish, and every participant who ever used Windows 95 would sense the difference without naming it.
- **Full desktop window manager (draggable windows, z-order, taskbar switching).** At the design interview, and again in the first writing of this note, the answer was no — **for this decision's original scope**: a 20-Question linear assessment had exactly one live program window, so multi-window machinery bought no comprehension and cost a11y and mobile layout. That history is kept visible because the reasoning was sound for the assessment flow, which still runs one window today: landing and quiz keep the layout-flow frame. *(Changed and shipped by tickets #59–#68, recorded by #69 — this is no longer the decision. What changed is the results stage, not the interview's arithmetic: it no longer holds one artifact in one place; it carries several multi-part artifacts that belong to different moments — the report settles at the click, the Action Plan arrives later from the Provider, the Deep-Dive Prompt is the thing taken away — and one scroll ran them together, so the late plan landed over the numbers that explain it and the Participant read the recommendation out of context. Giving each its own program surface separates the moments; the quiz stage was never widened. The two costs the refusal named are answered by construction rather than waived: the a11y cost is met by the inert keyboard floor (one Tab order, frames as labelled groups, no `aria-modal`, no Alt+Tab interception — Escape and the taskbar/shortcuts are the switching path), and the mobile cost by refusing to model a second layout at all: at ≤768px the viewport-blind core takes no Geometry write, every frame is full-screen, and the taskbar's three permanent program switches are the only route between them. See the shipped decision above.)*
- **Period-accurate bitmap type for body prose.** Rejected: 11-12px bitmapped text is unreadable for Scenario-length prose on modern displays, and legibility of assessment content is a product requirement, not a stylistic preference.
- **Pixel-art CJK font for the zh page.** Rejected: multi-megabyte full faces cannot be subset without a build step ADR 0001 forbids; SimSun-era system stacks are the period-accurate answer on the machines Chinese participants actually use. *(Reopened by #51: the premise no longer holds — an offline, repo-side fontTools subset (`scripts/subset-fusion-pixel.py`, not a page build) ships an ~889-glyph 34 KB woff2 under `fonts/` with the OFL text, so there is no runtime network request and no build step at render time.)*
