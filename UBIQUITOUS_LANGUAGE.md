# Ubiquitous Language

Domain vocabulary for the Agent Skills Security Self-assessment — extracted from the design session, `docs/architecture.md`, `docs/TESTING.md`, `questions.json`, the OWASP Agentic Skills Top 10 corpus, the post-redesign implementation rounds (UX redesign #13–#18, LLM pipeline hardening), the localization round (Bank Variants and Chrome Strings), the retro-OS shell and locale rounds (#38–#56: window chrome, faces, one-way first-visit routing, the in-page Locale Swap), and the desktop round (#59–#68 and the #70–#76 polish: three Program Windows, stacking and the right-anchored Arrival slots, shortcuts, the two taskbar rules, the inert keyboard floor, the per-tab desktop Record and its plan cache).

## Assessment content

| Term                 | Definition                                                                                          | Aliases to avoid                    |
| -------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------- |
| **Question Bank**    | The source of truth for assessment *content* in one language, parsed at load; the app's only runtime content database | Database (bare), question set, secondary content source |
| **Bank Variant**     | A Question Bank for one language, structurally identical to its sibling banks — same Question ids, Phase membership, AST Risk mappings, Option Scores, Severity Weights, and Title Ladder thresholds — differing only in authored text; the only content duplication the project permits (ADR 0015) | Translation file, locale bank, secondary content source, duplicate bank |

## Desktop shell

| Term                  | Definition                                                                                       | Aliases to avoid              |
| --------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------- |
| **Desktop Core**      | The DOM-free state module that owns every Window Record, the transitions between them, and the desktop gates; the codebase's only window state model — the Window Manager renders what it says | Window manager (that is the controller), state machine (bare), desktop state |
| **Program**           | One of the desktop's three fixed applications — Quiz, Action Plan, Deep-Dive Prompt. An identity, not a surface: the Quiz Program's answering, Results and Review stages are stages OF it, never programs of their own | App, application, tab, document |
| **Window**            | The one surface a Program presents on the desktop. Program and Window are one-to-one here; a Minimized or Put-Away Window still belongs to its Program | Panel, frame, popup, sub-window |
| **Program Window**    | A Program's single Window on the desktop — the **Quiz**, the **Action Plan** or the **Deep-Dive Prompt**. Only the Quiz Window exists from boot; the other two are born by Arrival | Panel, modal, popup, sub-window |
| **Running Window**    | A Window that is not Put Away. Exactly the Running Windows appear in the taskbar on the Desktop Layout, in the stable Program order; a Program that has not Arrived has no Window and no entry | Active window (that is the focused one), open window |
| **Arrival**           | The transition that creates a Window: it lands in the Program's own slot — the Quiz at its Designed Default Geometry near the desktop's left edge, the Action Plan in the fixed UPPER-right slot and the Deep-Dive Prompt in the fixed LOWER-right slot, both computed from the desktop's width by the Window Manager at a constant margin from the right edge — stacked below the active Window when it must not disturb the reading, and NEVER a focus call, a Raise or a scroll. The Action Plan arrives when its content settles; the Deep-Dive Prompt arrives Minimized at the Finish Commit. A designed slot, not an offset from whatever was focused, is the position an Arrival opens at | Spawn, popup, mount, show, cascade (retired) |
| **Window Record**     | One Window's state: Mode, Geometry, Last Geometry, Last Mode and stacking order | Window object, window model, window snapshot (bare) |
| **Window Mode**       | **Normal**, **Maximized**, **Minimized** or **Put Away**. The Mode is the contract: whether a Window is visible on the desktop, belongs in the taskbar, and participates in focus are all DERIVED from it, never stored | Window flags, open/closed, hidden (that is Put Away), minimized-boolean |
| **Minimize**          | Taking a Window off the desktop while KEEPING its taskbar entry, so returning is one click and needs no launcher. Minimize hands ACTIVATION to the topmost Window that is still visible — the one that comes to the front takes the navy title bar, the keyboard floor and the pressed switch with it; when no Window remains visible there is no active Window, and focus returns to the Program Switch that was pressed. Put Away is the other way off the desktop, and it leaves no entry | Collapse, hide (that is Put Away), close |
| **Raise**             | Bringing a Window to the front and making it the active one. Caused by pointer interaction inside it, by its taskbar switch, or by launching it when it already runs — never by Arrival | Focus (bare), bring to front, activate |
| **Window Restore**    | Returning a Minimized or Put-Away Window to its Last Mode and Last Geometry. The Window never left the desktop model, so nothing is rebuilt and no storage is read | Reopen, unminimize, reload |
| **End Request**       | The gesture — [×] on a Flow Stage, or Start-menu Quit — that asks the End Program question before anything is destroyed. On a Windowed Stage the Quiz Window's [×] is a Put Away instead; only Quit and Retake are End Requests | Close (bare), exit, shutdown |
| **Geometry**          | A Window's rectangle in desktop coordinates, the taskbar excluded. **Last Geometry** is the arrangement a Window Restore returns to; each Program also has a **Designed Default Geometry** — the Quiz's near the desktop's left edge, the two secondary Programs' as the reference-1024 fallback of their right-anchored slots — and the Window Manager computes each secondary Program's Arrival slot from the live desktop width at a constant margin from the right edge | Position, rect, bounds, cascade (retired) |
| **End Program Gate**  | The desktop-wide condition while the End Program confirmation owns the desktop: every other transition is refused until the question is answered | Modal lock, busy flag |
| **Windowed Stage**    | The stages behind the Finish Commit — Results and Review — where each Program is a positioned Window drawn from its Geometry, draggable and resizable. No desktop exists on any other stage | Desktop Regime (retired), windowed mode, floating panel, desktop (bare) |
| **Flow Stage**        | The stages before the Finish Commit — landing and answering — where the frame stays in layout flow, no Program Window runs, and [×] is an End Request | Desktop-less view, pre-desktop screen |
| **Desktop Layout**    | The wide layout of a Windowed Stage: positioned Windows that drag and resize above the Desktop Shortcut column on the surface behind them, and a taskbar listing only Running Windows | Desktop mode, wide layout |
| **Single-Program Layout** | The narrow layout of a Windowed Stage: one Program fills the screen above a slim taskbar, no Window can be moved or sized, chrome reduces to [×], and the taskbar's three permanent Program Switches are the only route between Programs | Mobile mode, mobile layout (as a domain name) |
| **Put Away**          | What [×] means on a Windowed Stage: the Window leaves the screen, the bare desktop and taskbar stay, and the Window Record, its Report and its arrangement survive the gesture. On the Desktop Layout the Put-Away Window leaves the taskbar and its Desktop Shortcut is the way back; on the Single-Program Layout its permanent Program Switch is. A Put-Away Window is never stranded, and a Flow Stage answers [×] with an End Request instead | Close (bare), quit, destroy, kill |
| **Program Switch**    | The taskbar entry for a Program. On the Desktop Layout only Running Windows have one; on the Single-Program Layout all three exist permanently whatever a Program's state, and exactly one reads pressed — the Program filling the screen. Activating one Raises, Window-Restores or Arrives its Window | Taskbar button (bare), alt-tab, app list |
| **Desktop Shortcut**  | One of the three fixed icons in the desktop's top-left column, one per Program, labelled with the same Chrome String the Program's title bar carries and drawn whether or not the Program runs. The column is the desktop's SURFACE, not chrome: it sits on the layer UNDER every Window, so a Window hides it — a maximized Window above all — and minimizing or moving that Window reveals it again. Coverage never strands a Program: a Put-Away Window is reopened from the front Window's way out — minimize or move the Window in front, and the shortcut answers — or, with no Window left standing over the column, directly. Activating one (double-click, Enter or Space) Arrives an unarrived Program, Window-Restores a Minimized or Put-Away one, or Raises a running one, and never duplicates a Window. Shortcuts exist on the Desktop Layout only | Icon (bare), launcher, tile, start-menu entry, always-visible column (retired) |
| **Chrome Handles**    | The two pointer affordances of a windowed frame: the title bar drags it and the bottom-right corner grip sizes it; both move the window by writing Geometry through the Desktop Core, never by touching the frame directly. Any pointer interaction inside a frame **Raises** it and makes it the active window | Drag area, resize border, gripper |
| **Section Mount Point** | The named place a movable results section renders into — the Action Plan and the Deep-Dive Prompt today. The same section renders into its own Program Window when one exists and in place when none does, and an in-place re-render re-mounts it rather than duplicating or orphaning it | Slot, container, placeholder |
| **Desktop Record** | The per-tab record of a COMMITTED desktop: the structural bank hash, the answers, the language, every Window Record and the active Program, created at the Finish Commit and replayed before the first paint; only a settled Action Plan amends it, through its Plan Cache. It is not the Session — the Session is the Participant's attempt and outlives the tab; the Desktop Record is this tab's arrangement and dies with it, and an uncommitted run leaves none. Nothing but Quit or Retake clears it | Session (bare), save slot, autosave, desktop snapshot (bare) |
| **Desktop Restore**   | Rebuilding a committed desktop on load: every Window returns in its recorded mode, stacking and arrangement, and the report is recomputed from the recorded answers. The only restore that reads storage — a Window Restore never does | Reload recovery, session restore (that is the Session), resume |
| **Plan Cache** | The settled Action Plan payloads carried inside the Desktop Record, one per (report, **language**), started empty at the commit. A Desktop Restore whose language is cached renders the plan without asking the Provider; a miss asks exactly once. A cleared Desktop Record is never rewritten, so a late resolution cannot resurrect a dead desktop | LLM cache, response cache, saved plan |
| **Menu Bar** | The strip of commands at the head of a Program Window's body. Two Program Windows own one and they differ in shape on purpose: the Quiz Window's is a true menu bar — Download PNG, Share Results, Review your answers, Retake Assessment — while the Deep-Dive Prompt Window's bar is the same strip surface carrying ONE flat command, the Copy Prompt Command, with no menu in it; the Action Plan Window owns none. Clarity over structural symmetry is the rule behind that difference. The Quiz bar's PNG command exports that body — score header, radar and bars — never the Window or its chrome | Toolbar, action row (retired), command buttons (retired), Quiz-only bar (retired), hamburger |
| **Quit** | The Start-menu command that ends a run: it asks the End Program question, and on Yes clears the Session and the Desktop Record, shows the landing page and destroys every Program Window. With Retake it is the only way to end a run; a page with no dialog tier asks nothing and destroys nothing | Exit, close (bare), power off |
| **Keyboard Floor** | The rule that only the focused Window answers the keyboard: a background Window's controls are unavailable to Tab while its pointer handles stay live, so focus never lands where the Participant is not working and a press there still Raises it. The floor follows the activation handoff — a Minimize passes activation to the topmost Window still visible, and where no Window remains visible every frame is floored and focus sits on the Program Switch that was pressed. Windows are labelled groups and never modal, with no focus trap and no intercepted window-switch shortcut | Focus trap, modal window, aria-modal frame |

## OWASP AST Risks

Canonical names and severities as titled in the Grounding Corpus (`docs/owasp-ast-full.md`). In code, the **ids** and **severities** live once in the AST Risk registry (`js/ast.js`) — see ADR 0013; the **display names** are Chrome Strings resolved from the locale dictionary, so each surface reads them from one place rather than keeping its own table. A Question's Severity inherits from the AST Risks it maps to. Severity is metadata and prompt data — it never renders in the Risk Radar or Blind-Spot Bars.

The ten names are a fixed terminology set per language, not text assembled per file. The Simplified Chinese set — 恶意技能 / 供应链入侵 / 权限过度的技能 / 不安全的元数据 / 不可信的外部指令 / 隔离不严 / 更新漂移 / 扫描不力 / 缺乏治理 / 跨平台复用 — is the deliberately chosen translation held in `i18n/zh.js` under ids `ast.AST01`…`ast.AST10`, and it is the single source for those terms. That is what keeps the Risk Radar, Blind-Spot Bars, Action Plan, Deterministic Fallback, and LLM Path prompt showing one consistent name per AST Risk: a **Bank Variant** supplies its own display names through its locale's dictionary and never re-declares them.

| Term                              | Severity | Definition                                                       |
| --------------------------------- | -------- | ---------------------------------------------------------------- |
| **AST01 — Malicious Skills**      | Critical | Attackers publish trojan skills through trusted channels and marketplaces |
| **AST02 — Supply Chain Compromise** | Critical | Compromise of dependencies or upstream components a skill relies on |
| **AST03 — Over-Privileged Skills**| High     | Skills request permissions beyond their stated function           |
| **AST04 — Insecure Metadata**     | High     | Skill metadata (SKILL.md) conceals or smuggles instructions       |
| **AST05 — Untrusted External Instructions** | High | Skills ingest remote content that steers agent behavior |
| **AST06 — Weak Isolation**        | High     | Insufficient sandboxing lets a skill reach beyond its scope       |
| **AST07 — Update Drift**          | Medium   | Installed skills change or degrade silently across updates        |
| **AST08 — Poor Scanning**         | Medium   | Invisible payloads (Unicode, base64) evade human review unscanned |
| **AST09 — No Governance**         | Medium   | No policy or process for approving and managing skills            |
| **AST10 — Cross-Platform Reuse**  | Medium   | A skill safe in one agent context misbehaves when reused elsewhere |

## Relationships

- A **Question** belongs to exactly one **Phase** and maps to one or more **AST Risks**.
- An **Option** belongs to exactly one **Question** and carries exactly one **Option Score**, one **Feedback**, and one letter badge (A–D).
- A **Session** records exactly one **Option** per **Question**; a structural bank change version-stamps stale Sessions while authored-text changes do not; **Wizard Navigation** moves both ways — re-answers overwrite in place and the card stays put (no advance on a revisit), and **Finish Commit** is the single path to **Completion**. One **Participant** has one Session for the whole assessment — every **Bank Variant** reads and writes the same record, so switching language resumes in place rather than starting a second run, and rewriting prose never costs anyone their progress (ADR 0017).
- The **Quiz Chrome** updates in place: the **Question Counter** shows the question being viewed, the **Progress Fill** shows answered/20, the **Phase Chip** swaps the Phase title — nothing stacks, nothing appends, and the bar stays pinned inside the fixed-height window while only the client area scrolls (#52).
- The **Language Toggle** performs a **Locale Swap**: dictionary, then Bank Variant, then `<html lang>`, `document.title` and the URL with one history entry, then a rebuild of the visible view from current state. The **Session**, the current **Question**, the **Completion**'s score report and the scroll position all survive it; a swap that cannot load its alternate leaves the language alone and says so in a dismissible notice (ADR 0019). Every successful swap writes the **Language Preference**, which is what keeps the swap the override over first-visit routing (ADR 0018).
- A **Completion** consumes one **Session**, produces exactly one **Progression Title** and one Action Plan request, opens the desktop stage and is the only moment the **Desktop Record** is created (a settled Action Plan later amends its **Plan Cache**); the **Progress Fill** holds 100% for a beat before the hand-off. A complete but UNcommitted Session is not a Completion — it resumes on the last Question with [Finish] live, and no boot path may ever render results from the Session alone (ADR 0020's explicit commit, recorded against ADR 0017's older sentence in ADR 0021).
- A **Blind Spot** is one **Participant**'s low **AST Score** on one **AST Risk**; a Multi-Mapping Question feeds every mapped **AST Score**, so one bad answer can open two Blind Spots.
- A **Best Practice** is Question-level; a **Mitigation** is AST-Risk-level (corpus). The **Deterministic Fallback** distills Best Practices into Actions; **Grounding Excerpts** carry Mitigations.
- On the **LLM Path**, every **Action** and the **Narrative** must trace to the **Grounding Material** — an **Action**'s AST Risk must be covered by the Grounding Excerpts or the Weakest Questions' Best Practices; the model name never reaches the client.
- The **Deep-Dive Prompt** is deterministic and identical on the **LLM Path** and the **Deterministic Fallback** — the **Narrative** (collapsed in the **Narrative Expander**) and the **Actions** differ between paths.
- A **Source Note** bounds what the LLM may claim; **Authoring-Time Validation** enforces it, **Runtime Validation** checks structure only. The shipped **Grounding Corpus** itself is gate-tested (all 10 AST Risks must extract cleanly).
- **Review** is its own screen, reached from the Quiz window's **menu bar**; it never shows scores or percentages.
- The **Desktop Core** owns exactly one **Window Record** per Program; the **Window Mode** alone decides whether that Window is visible, in the taskbar and eligible for focus, and the Window Manager renders from those derived answers instead of keeping a copy. Activation names ONE visible Window or none: **Minimize** hands it to the topmost Window still visible — the navy title bar, the keyboard floor and the pressed **Program Switch** all move with it — and when no Window remains visible the desktop has no active Window and focus returns to the Program Switch that was pressed. Every movable results section sits on its own **Section Mount Point** so the same content can be rendered in place or inside a Window.
- The **Desktop Shortcut**s and the **Program Switch**es are two launch gestures for one action — Arrive, Window-Restore or Raise — the Shortcuts on the Desktop Layout, the Switches permanent on the Single-Program Layout where there is no shortcut column. A Put-Away Window keeps its Record, its Report and its arrangement; nothing but **Quit** or **Retake** destroys one, and those two are the only gestures that clear the **Session** and the **Desktop Record**.
- The **Desktop Record** follows the **Finish Commit**, never the Session: an uncommitted run leaves no record to restore, and a Desktop Restore fires no `quiz_completed`. Its **Plan Cache** is keyed per (report, language), so a **Locale Swap** back to a language whose plan already settled re-renders from cache instead of asking the Provider again.

## Example dialogue

> **Dev:** "The Participant is on question 20 and the counter says 20/20, but the results aren't showing — bug?"

> **Domain expert:** "No — that's the designed gate. The first time an Option is tapped the card auto-advances on the beat; at the last answer the **Question Counter** holds 20/20 with the **Progress Fill** at 100% for a beat and **Finish** becomes enabled. **Completion** fires only on the **Finish Commit** — the old counter counted *answered* questions, which is why people thought the quiz ended at 19."

> **Dev:** "They went back and changed their answer on question 3 — does the **Session** keep both answers?"

> **Domain expert:** "One **Option** per **Question**, always — the new pick overwrites the stored one, the radio re-marks, and the card stays put: re-answering never auto-advances. Picks stay free until the **Finish Commit**."

> **Dev:** "Mid-quiz they hit 中文 in the **Language Toggle** and the page jumped back to the **Welcome Splash** — reload bug?"

> **Domain expert:** "There is no reload any more. A **Locale Swap** registers the other Chrome String dictionary, loads the other **Bank Variant**, updates `<html lang>`, the title and the URL, then rebuilds the view they were looking at — same **Question**, same answers, same scroll (ADR 0019). If you saw the Splash, they pressed it from the Splash; the toggle acts on whatever view is visible. And if it ever *appears* to navigate, that is the one deliberate case left: a view the swap module does not know, which keeps the old record-and-navigate action."

> **Dev:** "Where did the **Review** go? It used to sit right under the Action Plan."

> **Domain expert:** "It's its own screen and its own route — the **Quiz window's menu bar** carries the four commands (Download PNG, Share Results, Review your answers →, Retake Assessment), so the Quiz body below it holds only the score header, the **Risk Radar** and the **Blind-Spot Bars**. The **Action Plan** and the **Deep-Dive Prompt** are Program Windows of their own (#65/#61). The Review never shows scores."

> **Dev:** "And where's the plan's **Narrative**? I don't see it above the ranked action rows."

> **Domain expert:** "Collapsed in the **Narrative Expander** — the one `[＋]/[−]` disclosure row beneath the ranked list (#72). Same behavior on the **LLM Path** and the **Deterministic Fallback**, same schema either way."

> **Dev:** "What stops the Provider inventing a breach statistic?"

> **Domain expert:** "**Grounding Material**. The prompt carries the **Grounding Excerpts** for the weakest risks and the **Weakest Questions**' Best Practices, and instructs the model to trace every claim there — **Runtime Validation** checks structure only, and the corpus itself is gate-tested so a format edit can't silently empty the grounding."

## Flagged ambiguities

- **"title" still carries three meanings** — the app title (`meta.title`), the Phase heading (`phases[].title`), and the tier name (`meta.scoring.titles[]`). Domain term: **Progression Title**; say "app title" and "Phase heading" for the others, never bare "title".
- **"copy is data" narrowed** — the retired blanket claim no longer holds. Assessment *content* is still the Bank's; interface copy is a **Chrome String** resolved from the locale dictionary, and "no secondary content source" now means no secondary *source of assessment content*. A **Bank Variant** is not a second source — it is the same content in another language (ADR 0015).
- **"language" vs "locale" vs "translation"** — a **Bank Variant** is a whole Question Bank per language; the Chrome String dictionary is the per-language string table. Never call either a "translation file": the Variant is content, the dictionary is interface copy, and neither is generated at build time.
- **AST Risk display names are not code and not bank content** — ids and severities are code (`js/ast.js`), display names are Chrome Strings. A hardcoded AST name in any `js/` module is a regression (ADR 0013 as narrowed by ADR 0015).
- **"user" still forbidden** — **Participant** for the person assessed, **Agent** for their AI app.
- **"score" is never bare** — Option Score, Weighted Score, AST Score, and Overall Percentage are four distinct numbers. Always qualify.
- **"grade" is retired** — Progression Titles replaced it. Must not reappear.
- **"header" became overloaded after the redesign** — three surfaces: the landing header (title, subtitle, Start button), the retired **phase header card**, and the **Quiz Chrome**. The phase header card is retired vocabulary: the Phase now appears only as the **Phase Chip** inside the Quiz Chrome. Never re-add a phase block near the Question card.
- **"switching language" is a Locale Swap, not a navigation** — no document, comment or test may claim the language switch reloads or navigates: the two pages still exist and stay directly linkable, but the **Language Toggle** changes the language in place (ADR 0019), with the unknown-view record-and-navigate fallback as its single exception.
- **Retired interface vocabulary** — the first-visit **offer** dialog and its dismissal record (#54), the taskbar tray **clock** the **Language Toggle** replaced (#50), the "language tray chip" name for that toggle (#50), the floating/sticky quiz chrome bar the pinned **Quiz Chrome** replaced (#52), the separate Chinese stylesheet `css/cjk.css` (#51 — Chinese typography is now a rule set inside `css/theme-retro-os.css`, gated on `html[lang^="zh"]`, because a runtime Locale Swap rewrites `<html lang>`), the results-page **command buttons** and the fake **Title Card** window frame the Quiz window's **menu bar** and body-only score header replaced (#60/#65 — no module may draw a second title bar around report content, and the PNG export never copies window chrome), the #61 **Quiz button bridge** that kept a hidden Quiz window in the taskbar (#62 — a hidden window has no button on the desktop layout), and #62's **mobile ban on putting windows away** (a hidden window was stranded with no shortcut to restore it, so the mobile [×] was routed back to End Program and program frames' [×] was grayed — #68 retired all of that: the permanent taskbar switch is the route back and [×] puts any window away on either layout). Say **Language Toggle**, **Locale Swap**, **Welcome Splash**, **Quiz Chrome**, **Menu Bar**, **Put Away**, **Program Switch**, **Desktop Record**, **Plan Cache**, **Keyboard Floor**.
- **"progress bar" vs "counter"** — two different signals: the **Question Counter** shows the question being *viewed*; the **Progress Fill** shows answered/20. They were conflated before the redesign (the "quiz ended at 19/20" confusion) — never use bare "progress".
- **"restore" is never bare** — **Window Restore** (a window's mode and arrangement) and **Desktop Restore** (rebuilding a committed desktop from its record) are different operations on different objects, and only the second reads storage.
- **"close" is not a domain act** — the [×] glyph is a **Put Away** on a Windowed Stage and an **End Request** on a Flow Stage. Say the outcome, never the glyph: "close" appears in no definition, and "closed" is not a Window Mode.
- **Severity Chip is retired from visuals** — owner decision: severity (critical / high / medium) no longer renders in the Risk Radar or Blind-Spot Bars; it lives only as bank/corpus metadata and as prompt data. Score-band colors alone encode the Participant's performance.
- **"upstream" vs "provider"** — ADR text says "upstream LLM endpoint"; in domain conversation say **Provider**. "Upstream" is acceptable only as infrastructure phrasing inside the Proxy Worker's code and ADRs.
- **Analytics event contract drift** — RESOLVED 2026-09-10: the contract is now **five events** (`quiz_started`, `quiz_completed`, `llm_success`, `llm_fallback`, `template_copied`), recorded as an amendment comment on PRD issue #1. `quiz_started` fires once on Start.
- **"prompt template" vs "deep-dive prompt"** — canonical: **Deep-Dive Prompt**; "template" collides with code templates.
- **"static-recommendations" and "grade" remain dead vocabulary** — use **Deterministic Fallback** and **Progression Title**.
